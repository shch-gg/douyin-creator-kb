# 20 · 博主收编（从主页到作者档案）

> 用户给的可能不是一条链接，而是"把这个博主全拆了"。
> 这条路比单条重：要解决**收哪些、收多少、怎么上卷、系列怎么算**。

---

## 第 1 步 · 收编范围决策（先定，别边做边改）

拿到主页后，先出**作品清单**（`_inbox/<c-name>.csv`：标题 / aweme_id / 时长 / 发布时间 / 点赞 / 是否系列），再按下面三策选一：

| 策略 | 适用 | 收录量 | 代价 | 能得出什么 |
|---|---|---|---|---|
| **A 全量收编** | 作品 ≤20 部，或用户明确要求 | 全部 | 高 | 作者级完整结论、轨迹、系列引擎 |
| **B 分层抽样** | 作品 20–100 部 | 8–12 部：爆款 Top3 + 中位 4 + 早期 2 + 最新 2 | 中 | 指纹可用（≥4），轨迹粗略 |
| **C 序列优先** | 有连续剧/系列 | 优先拆完整系列（≥3 集） | 中 | 系列引擎、集末钩子、连续性手法 |

**硬门槛**：

- 要写「稳定手法」→ 至少 4 部独立作品
- 要出「生长轨迹」→ 必须覆盖早期（最早 2 部）+ 近期（最新 2 部），中间可抽
- 要出「系列引擎」→ 该系列至少 3 集，且包含结局集

**先跟用户确认抽样策略再动手**。做完 20 部才说"其实只要 5 部"，是最贵的返工。

## 第 2 步 · 建博主档

```bash
# 博主不存在时，new_work.py 会自动建 c-NNNN；也可先建一部占位作品再补
python3 _pipeline/new_work.py --creator "<博主名>" --title "<首部作品名>" \
    --aweme <aweme_id> --duration-ms <ms>
```

生成 `creators/c-NNNN/`：

```text
profile.json       # 定位、形态、标签、更新节奏、works_count
index.md           # 账号画像（先写"初判"，收编后重写）
fingerprint.md     # 作者指纹（模板骨架，收编前为空）
matrix.md          # 十维 × 作品（骨架）
trajectory.md      # 生长轨迹（按发布时间留空表）
```

**初判纪律**：只允许写三件事——他是谁、做什么形态、给谁看。
**不许**在只看 1 部时就写"他擅长情绪调度"——那是 E3 判断，需要 ≥3 部支撑。

## 第 4 步 · 逐部走九闸门

每部按 `methods/10-入库SOP.md` 走。**允许并行前处理**（抽帧/OCR/Whisper 是 IO+CPU 密集，可排队跑），**不允许并行跳过精读**。

批量前处理的坑：

- 4 核配额，最多 3–4 个 worker，多了互相踩踏（实测 8 worker 时单帧 OCR 从 5s 涨到 39s）
- OCR 的 `det_limit_side_len` 调到 480 后，中部旁白板仍要全尺寸，否则会认错字

### 5.1 `fingerprint.md` 作者指纹

**定义**：换一部片子，哪些东西**不变**。

| 指纹维度 | 具体看什么 | 证据要求 |
|---|---|---|
| 开场 | 前 3 秒给什么：人物/异常/结论/提问 | 每部标类型 + 秒号 |
| 信息释放 | 设问—延迟—兑现的间隔结构 | 至少 3 部的间隔长度 |
| 文字系统 | 字幕板/旁白板/字卡的位置、字体、出现节奏 | 位置 + 平均停留秒 |
| 镜头 | 景别偏好、是否手持、平均镜长 | 平均镜长 + 极值 |
| 声音 | 是否有纯音乐段、静默用法、配乐进入点 | 秒号 |
| 转场 | 硬切/叠化/黑场/白闪的比例 | 各类计数 |
| 母题 | 反复出现的意象/道具/台词句式 | 至少 2 部出现才算 |
| 集末 | 钩子类型：悬念/反转/情绪落点 | 每部标类型 |

**每条指纹的格式固定**：

```md
### F-03 字幕板固定在画面中部偏上，每行 ≤14 字
- 支撑：w-0003 `t=030–035s`、w-0007 `t=062–069s`、w-0011 `t=104–108s`
- 变体：w-0009 灵堂段改用顶部单行（场景特殊，不算破例）
- 反例：w-0015 全片无字幕板（口播型）
- 置信度：stable（3 部支撑 / 1 变体 / 1 反例）
```

**没有反例要写清"为什么找不到"**，不许假装没有例外。

### 5.2 `matrix.md` 能力矩阵

十维 × 每部作品，0–10。空格写 `—` 并在表下说明"未评"原因。矩阵的作用是看**同一个人在不同题材上的强弱漂移**，不是排名。

### 5.3 `trajectory.md` 生长轨迹

按 `published_at` 升序排，标三类节点：

- **转折点**：手法明显变化的那部（要写"变了什么、可能为什么"）
- **能力跃迁**：某维从 ≤5 到 ≥8
- **退化**：某维连续 2 部下降

**不许**把"更新时间顺序"当成"在进步"。没有证据就说"未见明显变化"。

## 第 6 步 · 系列引擎（有系列才做）

`creators/c-NNNN/series/s-NNNN.md`：

| 项 | 要回答 |
|---|---|
| 系列类型 | 连续剧情 / 主题系列 / 同世界观 |
| 续作凭什么成立 | 未解的欲望、未兑现的威胁、未揭开的信息 |
| 集末钩子 | 每集最后一格是什么类型，兑现了几次 |
| 单元结构 | 每集是否可独立看，独立性来自哪 |
| 疲劳风险 | 第几集开始重复，重复在哪一层 |

**样本口径**：系列 N 集在知识卡里只算 **1 部**。系列页里可以写"第 N 集已验证"，但 `sample_size` 不涨。

---

## 第 7 步 · 触发知识提炼

一家博主收编完，至少产出 3–6 张卡（见 `methods/30`）。**其中至少 1 张必须是"这个博主独有的"**，否则等于只做了通用分析。

判据：如果这张卡换成任何同赛道博主都成立，它就不是"作者级发现"，只是行业常识。
